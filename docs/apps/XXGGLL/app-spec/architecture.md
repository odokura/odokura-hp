# XXGGLL アーキテクチャ

本ページは、XXGGLLのシステム構成、モジュール分割、外部連携を扱う**アーキテクチャの正本**である。業務ルールは
[構想](../concept/overview.md)を正本とし、本ページでは実装に必要な範囲でのみ参照する。想定運用規模は
小規模（[概要](./overview.md)の「設計の芯」）であり、規模に見合わない分散構成は採らない。

## 確定事項

| 項目 | 方針 |
| --- | --- |
| 実行形態 | 多数のクリエイター・多数のユーザーが使うマルチテナントのサービスだが、想定運用規模は小規模。単一の小さなアプリケーション（モノリス）として構築し、マイクロサービス分割はしない |
| 正本データ | サーバー側の単一リレーショナルDB（PostgreSQL）。証票・台帳・同意・監査ログを同じDBで一元管理する。ホスティングはRailwayを第一候補とする（→ [ベンダー選定](./vendor-selection.md)） |
| 決済データ | カード情報・銀行口座情報は自社インフラを通過させない。決済代行はStripe Connectを第一候補とする（→ [ベンダー選定](./vendor-selection.md)）。自前の決済基盤は作らない |
| 決済の受け取りタイミング | 一次発行・継続支援・証票支援・二次流通の再発行価格は、運営が売上としてStripeの運営プラットフォーム残高へ受領する（Separate Charges and Transfers）。二次流通の前保有者には現金送金を行わず、再発行クレジットを付与する。クリエイターには別契約に基づく報酬・別契約対価を、通常は決済確定から90日経過後の本人の出金申請時にだけ送金する。Stripe側の本人・口座確認・サービス契約同意はこの申請時に発生する。海外送金はStripeが有効と判定した国・通貨・経路に限る |
| クライアント | Web。対応言語は日本語のみとする |
| 運営系アクセス | 単一の管理画面（/admin）をロールベースで出し分ける。役割ごとに別コンソール・別インフラを用意しない |

## システム構成

```text
一般ユーザー / クリエイター（Web クライアント）
        │ HTTPS
        v
  アプリケーション（単一のバックエンド。分割はコード内のモジュール単位で行う）
        ├─ カタログ・購入・属性共有・継続支援・出品
        ├─ 台帳モジュール（一次支援・継続支援・証票支援・二次再発行・S1/S2の按分記帳、再発行クレジットの
        │   付与・利用・6か月失効。出金申請を受けて、Stripeで送金可となったクリエイターへの送金を実行する）
        ├─ 在庫・価格モジュール（15分の在庫仮押さえ、発行数・価格のルールベース算出）
        ├─ 属性共有・同意モジュール（項目別同意・撤回・クリエイター向け集計ダッシュボードの生成）
        ├─ モデレーションモジュール（私的連絡先・禁止表現の自動検出、通報キュー）
        ├─ VIPコンシェルジュモジュール（専用スレッドの状態遷移、匿名打診）
        └─ 管理画面（/admin。ロールベースで機能を出し分ける単一の管理UI）
        │
        v
  単一のプライマリDB（想定: PostgreSQL。選定は[技術検証計画](./tech-verification.md)）
        ├─ 証票・台帳・同意
        └─ 監査ログテーブル（追記専用。アプリのDBロールにUPDATE/DELETE権限を持たせない）

外部連携: 決済代行（Stripe Connect想定。Separate Charges and Transfersで買い手の支払いを一旦運営残高へ
集約し、出金申請時にだけStripeが本人確認・口座確認済みと判定したConnected Accountへ送金する。海外送金は
Stripeが有効と判定した国・通貨・経路だけで行う。前保有者への対価は再発行クレジットであり送金しない）。
```

## モジュールの責務

| モジュール | 責務 | 関連する構想ページ |
| --- | --- | --- |
| カタログ・購入 | 利用者セッション、カタログ表示、購入・属性共有・継続支援・出品の受付 | [一般ユーザーとの関係](../concept/general/relationship-general.md) |
| 台帳 | 一次支援・継続支援・証票支援・二次再発行・S1/S2の按分記帳、再発行クレジットの付与・利用・6か月失効、証票支援累計額の加算、返金の対称取り消し、出金申請に応じたクリエイターへの送金。送金前にConnected Accountの送金可否・国・通貨を検証する | [取引ルール](../concept/general/transaction-general.md) |
| 在庫・価格 | 在庫仮押さえ（15分）、待機需要の簡易重複防止、発行数・価格のルールベース算出 | [価格・発行数の算出](../concept/general/pricing.md) |
| クリエイター報酬受領確認 | Stripe Connectのホスト型オンボーディングでStripeが本人確認・事業者確認・振込先確認を行い、XXGGLLは状態とConnected Account IDだけを扱う | [属性開示・決済事業者確認](../concept/foundation/identity-disclosure.md) |
| 属性共有・同意 | 項目別同意の記録・撤回・譲渡時の終了、クリエイター向け集計ダッシュボードの生成 | 同上 |
| モデレーション | 私的連絡先・禁止表現の自動検出、通報・非表示キュー | [関係記録・コンテンツ](../concept/benefits/content.md) |
| VIPコンシェルジュ | 専用スレッドの状態遷移、匿名打診、最終条件の合意記録 | [VIPコンシェルジュ運用](../concept/vip/vip-concierge.md) |
| 管理画面 | admin・creator_staffロールでの参照・運用操作。すべての操作を監査ログへ記録 | [セキュリティ](./security.md) |

## アクセス制御

- 利用者・クリエイター向けAPIはカード情報・本人確認書類を直接扱わない。決済情報と報酬受領確認はStripeの
  ホスト型画面へ委譲し、XXGGLLは必要なトークン・状態だけを受け取る。
- 管理画面はログイン後にロール（admin・creator_staffなど）で機能を出し分ける。別ドメインや別インフラを
  必須にはしない。運用規模が拡大した場合に分離を検討する（[決定ログ](./decisions.md)）。
- クリエイター向け画面・APIは、法的氏名・住所・本人確認書類・決済カード情報を一切返さない
  （構想の原則をAPI応答レベルで強制する）。

## 非目標

- マイクロサービス分割、役割ごとの専任コンソール、承認ワークフローエンジン、改ざん検知基盤など、
  運用規模に見合わない基盤は最初から作らない（[決定ログ](./decisions.md)）。
- NFT・暗号資産基盤は使わない（[コンセプト](../concept/foundation/concept.md)）。
- クリエイター向けにCSV等の一括エクスポートを既定で提供しない（[一般クリエイター](../concept/general/creator-general.md)）。
- クライアント側での価格・発行数計算は行わない。算出はサーバー側モジュールに閉じる。
