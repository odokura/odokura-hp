# XXGGLL UX

## この文書の責務

UXは、利用者が画面を開いてから「何を理解し、何を選び、何が記録されたか」を定義する。
色、フォント、装飾、CSSの実装方法は[デザイン仕様](./design.md)、ルート・read model・認可・状態は[画面台帳](./screen-catalog.md)が所有する。

## 利用者の中心課題

| 利用者 | 最初に解く問い | 画面が返すべき結果 |
| --- | --- | --- |
| 未認証のFan | この個別案内は何を残すのか | 対象、条件、役務が発生しない境界、次の確認 |
| 認証済みFan | 自分はいま何を保有し、何が記録されているか | 現在状態、要対応、保有対象、来歴、次の操作 |
| Creator | 発行したXXGGLLと保有者全体の傾向をどう判断に使うか | 発行状態、匿名集計、収益状態、必要な設定 |
| staff | 許可されたCreator管理の仕事を何から進めるか | 対象Creator、許可範囲、状態、次の仕事 |
| admin | どのケースを安全に処理すべきか | 対象、根拠、影響、期限、一つの確定操作、監査 |

利用者をロール選択画面へ送らない。アクセスできる機能をサーバーが確定し、画面はその結果から次の目的だけを示す。

## 情報構造

XXGGLLの基本単位は「一件の関係記録」である。画面は次の順で意味を組み立てる。

```text
対象
  → 現在状態
    → 次の一手
      → 取得時点・番号・条件
        → 連続した来歴と補足
```

- Homeは現在の保有と要対応を最優先にする。
- 保有詳細は一件の状態と来歴を扱い、活動全体や設定フォームを混ぜない。
- Creator管理は発行プログラム、ファン全体の傾向、収益・精算、別契約の提供物、設定・権限を責務ごとに分ける。
- Opsは一件のケースを確認して一操作を確定する。全データのダッシュボードにしない。
- Publicは製品の世界と仕組みを説明し、公開カタログ・検索・人気順を提供しない。

## ナビゲーション

### Home

デスクトップは次の順序を固定する。

```text
XXGGLL

ホーム

あなたの記録
  保有XXGGLL
  活動の記録

Creator管理（権限がある場合だけ）
  発行プログラム
  ファン全体の傾向

アカウント
  プロフィール
  設定
```

- Creator管理をアカウント設定へ隠さない。
- Home本文にはナビゲーションの説明を繰り返さず、現在状態 → 要対応 → 保有対象 → 発行対象の順で表示する。
- クリエイターのプロフィール自体を発行カードに変換しない。発行カードは`issuance_program`単位にする。
- モバイルの固定ナビは`ホーム | 保有XXGGLL | 活動の記録 | その他`の4項目以内とし、Creator管理・プロフィール・設定は`その他`に置く。

### Creator管理

Creator管理は独立したブランドやコミュニティではなく、認可されたCreatorの仕事を完了するための機能群である。

- 一つのCreatorだけを管理できる場合は、選択画面を挟まず概要へ進む。
- 複数のCreatorを管理できる場合だけ対象Creatorを選ばせる。
- サイドメニューは「概要 → 発行プログラム → ファン全体の傾向 → 収益・精算 → 別契約の提供物 → 設定・権限」の順とし、詳細は[Creator管理](./creator-management/overview.md)を正本とする。
- 発行、集計、収益、別契約、権限設定を同じ一覧へ混ぜない。
- URLの`creatorId`だけで対象を決めず、owner/staff権限を要求ごとにサーバーで確認する。
- 個人ファン一覧、匿名識別子検索、営業リスト、無制限CSV出力を標準導線にしない。

### Ops

Opsは、専用Originと利用者検証済みパスキーを持つadminだけの運用面である。
通常の利用者にOpsの存在、admin権限、credentialの有無を表示しない。Opsの本文は対象 → 根拠 → 影響 → 操作 → 結果 → 監査の順にする。

## 主要導線

### Fanの取得

```text
Creatorから案内された個別リンク
  → 対象・条件・役務境界の確認
    → 認証（必要な場合）
      → 同じ対象の取得確認
        → 決済・取得処理
          → 反映待ちまたは成功
            → Home / 保有詳細
```

- 個別リンクがないFanに公開一覧・検索・推薦を提示しない。
- 認証後は検証済みの同じ個別リンクへ戻す。
- 取得だけでは返信、制作、物品、接客、面会などの個別役務は発生しないことを、価格や確定操作の近くで示す。
- 決済やWebhookの反映待ちを成功と表示しない。再課金なしの再確認方法を示す。

### Fanの振り返り

Homeでは現在の保有と要対応だけを示し、活動の記録では一次取得、継続、追加支援、グッズ、返金・取消を区分して時系列に表示する。
金額だけの進捗バー、他者順位、到達保証、前保有者の個人情報を表示しない。

### Creatorの判断

概要は次の一手だけを返し、各機能の縮小版を並べない。
[発行プログラム](./creator-management/programs.md)は下書き・条件・公開状態・発行数・要対応・次の操作を扱う。
[ファン全体の傾向](./creator-management/audience.md)は母集団、地域、ランク、確認済み支払額帯、保有期間、任意プロフィール、グッズを、個人との対応を排した集計として扱う。
集計値が未確定のときは0件に補完せず、基準時刻、母数不足、取得失敗を区別する。個人の応援文やプロフィールカードは集計へ混ぜない。

## 共有と境界

プロフィールは、入力した本人と開示先を混同させない。

- アカウント名・出身国地域の自動開示と、任意プロフィールの項目別共有を別の意味として示す。
- 任意プロフィールの各項目は現在および今後の全発行者へ共有するかを管理し、共有先を個別指定する機能は作らない。
- Public公開と発行者への共有を同じ「公開」ラベルで表さない。
- 共有設定は項目ごとの現在状態、共有先件数、共有項目、未共有情報を一つの境界として読めるようにする。初期表示は閲覧モードとし、編集モードで個別チェックを操作する。
- 共有失敗時はサーバー確定値へ戻し、プロフィール項目の保存失敗は入力内容を保持して再試行できるようにする。

## 状態の意味

UXは、状態を色名ではなく利用者の次の行動で表す。

| 状態 | 利用者に伝えること | 次の行動 |
| --- | --- | --- |
| 読み込み中 | 何を取得しているか | 待つ |
| 空 | なぜ空か | 次の一手を一つ選ぶ |
| 処理中 | 何を一度だけ送ったか | 二重操作せず待つ |
| 反映待ち | 外部処理のどこを待つか | 再課金せず再確認する |
| 成功 | サーバーで何が確定したか | 記録または次の画面へ進む |
| 要対応 | 原因、影響、期限、復帰方法 | 対応または問い合わせ |
| 未認証 | 認証が必要なことだけ | 許可された復帰先へ進む |
| 認可なし・不存在 | 対象の存在を推測できないこと | Homeまたは戻る |

## 完了条件

- 画面を開いた利用者が、最初の表示領域で対象・状態・次の一手を判断できる。
- 同じ業務上の問いが、複数の画面やロールで別の名称・順序に分裂していない。
- 公開範囲、個人情報、役務、決済、権限の境界が、画面の主目的と矛盾しない。
- 失敗、再試行、反映待ち、競合、期限切れ、権限なしを成功や空に潰していない。
- 画面台帳にあるルート・状態・受け入れ条件と一致し、視覚的な判断はデザイン仕様へ委譲している。
