# XXGGLL Public費用ページ仕様

## 1. 目的

Public費用ページ（`/pricing`）は、Fanが「何に、いつ、いくら払うか」を短時間で比較し、
Creatorが受け取る報酬とは別の金額であることを理解するための意思決定ページである。

Railway Pricingの「価値を一文で示す、選択肢をカードで比べる、詳細を比較表で確認する、疑問をFAQで解消する」
という情報設計を参照する。ただし、ブランド表現、文言、図版は複製せず、XXGGLL固有の費用モデルへ置き換える。
読み終えた人が、次の三点を説明できることを成功とする。

- Fanは、XXGGLL価格、決済手数料、税、合計、次回の継続支援を確定前に確認する。
- Fanは、初回取得、年額継続、追加支援、商品・個別サービスの違いを比較できる。
- Creatorは、Fan支払額ではなく取引ごとに算定されたCreator報酬を、保留中・精算可能・申請中に分けて確認する。

## 2. 画面契約

| 項目 | 契約 |
| --- | --- |
| ルート | `/pricing` |
| シェル | Public |
| 利用者 | 未認証者、認証済みFan、発行を検討するCreator |
| 最重要の理解 | 初回、年額、任意支援、別契約は発生時点と含まれるものが異なり、支払合計とCreator受取額も同じではない |
| 主要操作 | `/flow`または`/safety`へ進む。購入確定操作は置かない |
| データ境界 | 静的な構成例だけを使い、実在する価格、取引、報酬、精算を取得しない |
| 対象外 | 一律価格表、公開カタログ、Creator比較、取得確定、手数料0円または未確定料率の表示 |

## 3. 読む順序

ページは次の順にする。

1. 費用原則を一文で伝えるHeroと、初回から年額までを示す簡潔な図
2. B-01未解決中は有料取得を開始しない現在状態
3. 初回取得、年額継続、追加支援、商品・個別サービスの費用カード
4. 請求前に価格・決済手数料・税・合計を分ける支払内訳
5. 四つの費用を、発生時点、金額の決まり方、含まれるもの、自動更新、役務の有無、停止方法で比べる比較表
6. Creator報酬の取引ごとの算定、通常90日の保留、精算申請
7. 請求、更新停止、取消・返金、決済反映待ち、役務境界のFAQ
8. `/flow`と`/safety`への導線

## 4. Fanへ説明する費用

| 場面 | 説明 |
| --- | --- |
| 最初の取得 | カードでは`個別価格`、`最初の1回`と示す。XXGGLL価格には最初の12か月の継続支援を含み、個別リンクで価格、決済手数料、税、合計、支払済み期限を確定前に表示する |
| 13か月目以降 | カードでは`基準価格の10% / 年`と示す。決済可能な最低金額を下回る場合は最低金額とする。年額と次回決済日を取得前とHomeで表示し、次回更新の24時間前まで自動継続を停止できる |
| 任意支援 | カードでは`自分で金額を選ぶ`、`必要なときだけ`と示す。XXGGLL保有中の別決済として、対象、金額、反映先、取消条件を確定前に示し、個別役務を発生させない |
| 商品・個別サービス | カードでは`別に提示`、`申し込むときだけ`と示す。XXGGLL価格へ含めず、内容、価格、期限、返金条件を持つ別契約・別決済として扱う |

更新停止は返金ではない。停止後も支払済み期限までは現在状態を維持し、次回分を課金しない。
プログラム終了だけを理由に支払済み期間を日割り返金しない。決済反映待ちは完了とせず、再課金を防ぐ。

## 5. Creatorへ説明するお金

- Fan支払額をCreatorへの預り金または固定割合の分配として説明しない。
- Creator報酬は、決済手数料、返金・異議申立ての見込み、運営上のリスク留保を織り込み、取引ごとに算定する。
- 通常の報酬は決済確定から90日後に精算可能とする。確認が必要な取引は最長180日まで保留できる。
- Creator管理では精算可能額、保留中、申請中を分ける。
- 初回の精算申請でStripeの本人確認・口座確認を行い、送金可否の確認前は送金しない。
- 確定・支払済みのCreator報酬は、通常の購入者返金・チャージバックを理由にCreatorから相殺・回収しない。

## 6. B-01未解決中の表示

利用者負担の決済手数料は、算定式、端数処理、確定時点、保存先、返金時の扱いが未確定である。
未解決中は次を守る。

- `購入機能は現在準備中です。`と表示する。
- 手数料0円、固定料率、金額入りの表示例を置かない。
- 購入可能、購入を確定、今すぐ取得等の操作を置かない。
- 手数料を画面から隠してXXGGLL価格だけを総額として見せない。
- `/pricing`から個別リンク、公開一覧、検索、Creator一覧へ遷移させない。

## 7. ビジュアルとアクセシビリティ

- Heroは大きな価値訴求と、初回から年額までの費用発生を示す抽象グラフを左右に置く。
- Hero直下に、四つの費用カードを同じ列幅で並べる。カードは金額の決まり方、発生頻度、対象者、含まれるもの、比較導線を同じ位置に置く。
- 比較表は先頭列を比較項目、残り四列を費用種別とし、ヘッダーを追従表示する。狭幅では横スクロール領域とし、ページ全体は横にはみ出させない。
- FAQは`details`と`summary`を使い、キーボードだけで開閉できる。
- FanとCreatorは同じ背景・余白・見出し体系を使い、アクセント色だけで意味を伝えない。
- 1440pxでは四列、900px以下では二列、560px以下では一列にする。
- 5項目のPublicナビは320pxで横スクロールさせず、44px以上の操作領域を保つ。
- forced colors、reduced motion、キーボード操作で内容とリンクを失わない。
