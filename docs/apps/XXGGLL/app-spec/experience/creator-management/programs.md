# Creator管理 発行プログラム

## 1. 画面群

| 画面ID | 正規ルート | read model / command | 目的 |
| --- | --- | --- | --- |
| `SC-S03` | `/studio/[creatorId]/programs` | `RM-IssuanceProgramList` | 一件一行で状態と次の操作を確認する |
| `SC-S04` | `/studio/[creatorId]/programs/new` | `RM-IssuanceDraftStart` / `CreateIssuanceDraft` | ownerが一度の操作で下書きを一件作る |
| `SC-S05` | `/studio/[creatorId]/programs/[programId]` | `RM-IssuanceProgramDetail` | 一件の条件、公開、終了、記録を管理する |

## 2. 一覧

ページ名は「発行プログラム」、説明は「発行するXXGGLLの状態と、次に必要な対応を確認できます。」、主操作は「発行プログラムを作成」とする。`Issued XXGGLL`、`Offers`、`発行カード`を同じ対象の別名として表示しない。

一覧はカードグリッドではなく、一件一行の比較可能なリストにする。既定順は`要対応 → 状態 → updated_at DESC → id DESC`の安定順とし、50件単位のcursor paginationを使う。

| 列 | 内容 |
| --- | --- |
| 対象 | XXGGLLランクとプログラムを識別できる短い名称 |
| 状態 | 下書き、需要計測中、審査中、公開中、終了処理中、終了 |
| 発行 | 発行済み件数 / 確定発行数。未確定は「未確定」 |
| 現在保有 | 現保有関係があるXXGGLL件数。人数ではない |
| 要対応 | 理由と期限。正常時は空欄 |
| 更新 | サーバー更新時刻 |

行全体をリンクにする場合も、行内の別操作を混在させない。新規作成はヘッダーの主操作一つにする。

## 3. 下書き作成

ページ名は「発行プログラムを作成」、説明は「公開前の下書きとして、ランク、上限、価格方式を設定します。」とする。公開・販売が同時に始まるような文言を使わない。

作成は次の順序に固定する。

1. 対象Creatorとowner権限をserverで確認し、読取表示する。
2. 発行するランクを一つ選ぶ。
3. 発行上限を整数で入力する。
4. 価格方式を選び、必要な場合だけ価格を入力する。
5. 作成後に確定する内容と、まだ公開されないことを確認する。
6. 「下書きを作成」で一件だけ作成し、詳細へ進む。

client mutation IDを必須にし、通信再送は同じ下書きを返す。二重送信、同ランク重複、権限失効、規約未同意、価格規則不成立を別の失敗として扱い、部分作成を成功表示しない。

## 4. 詳細

ページ名は「発行プログラム詳細」とし、対象バーの下にランク、表示用プログラム名、現在状態を置く。技術IDを`h1`にしない。

詳細は次の区画順にする。

1. 現在状態と次の一操作。
2. 発行条件: ランク、発行上限、確定発行数、価格方式、価格、通貨。
3. 公開条件: 審査、本人・正規提供者確認、規約、個別案内リンク。
4. 発行結果: 発行済み、予約中、現在保有、回収・終了。
5. owner限定の現在保有者。
6. 変更履歴と基準時刻。

編集、公開、終了を一つのフォームへ混ぜない。公開・終了は表示した`version`と確定時の`version`を比較し、競合時は保存せず全体を再取得する。

## 5. 現在保有者の限定開示

個人行はAudienceではなく、この区画だけに置く。

- 対象プログラムのownerだけが開ける。staffには区画の存在、件数、API routeを返さない。
- 各行は現在保有する一件のXXGGLLを基準とし、アカウント名、出身国・地域、その現保有者が当該XXGGLLを取得した価格、共有中の入力済み任意プロフィールだけを返す。
- 継続、証票支援、グッズ、他のXXGGLL、前保有者の金額・プロフィール・メッセージを返さない。
- 閲覧時にowner、対象Creator、対象プログラム、現在保有関係、共有フラグを再照合し、監査eventを残す。
- 検索、Creator横断一覧、CSV、コピー用連絡先、外部出力を提供しない。
- 譲渡・返還・回収と同時に資格が変わった場合は、古い行を返さず再取得する。

## 6. 状態と受け入れ条件

- 発行数、確定発行数、現在保有XXGGLL数、現在保有者数を同じラベルで表示しない。
- 0件、検索結果0件、取得失敗、permissionなしを別状態にする。
- 下書き、公開中、終了処理中、終了で許可される操作をserver commandと一致させる。
- 公開リンクが無効・期限切れの場合、旧リンクを表示せず再発行または確認の次操作だけを示す。
- ownerとstaff、他Creator、前保有者、譲渡競合、再送、複数tabのversion競合をE2Eで確認する。
- 旧`/offers/[programId]`からの移行は[Creator管理概要](./overview.md)の転送契約に従う。
