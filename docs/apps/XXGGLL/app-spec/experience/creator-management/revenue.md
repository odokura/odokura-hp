# Creator管理 収益・精算

## 1. 画面契約

| 項目 | 仕様 |
| --- | --- |
| 画面ID | `SC-S08` |
| ルート | `/studio/[creatorId]/revenue` |
| read model | `RM-CreatorRevenue` |
| 利用者 | owner、`revenue_read`を持つstaff |
| 更新操作 | ownerだけが出金準備・出金申請を実行できる |

この画面はCreator報酬の状態を確認し、出金可能な場合だけ一件の申請を行う。運営売上、Fanの支払総額、Stripe残高をCreator報酬と同じ金額として表示しない。

## 2. 表示順

ページ名は「収益・精算」、説明は「Creator報酬の確定状態と、出金できる金額を確認できます。」とする。「売上」「残高」「収益」を同じ金額の別名として混在させない。

1. 通貨ごとの精算可能額と最終更新時刻。
2. 要対応: 本人確認、口座確認、申請失敗、外部反映待ち。
3. 状態別内訳: 確認中、精算可能、申請中、送金済み、取消。
4. 取引区分別内訳: 一次発行、継続支援、証票支援、二次再発行。
5. 出金申請履歴。
6. 算定・保留・取消の説明。

staffには金額を読取表示できるが、出金操作、Stripe onboarding、口座・本人確認状態の詳細を操作可能にしない。口座番号、本人確認書類、Stripe account IDを応答へ含めない。

## 3. 金額状態

| 状態 | 定義 | 操作 |
| --- | --- | --- |
| 確認中 | 決済確定後の通常確認期間または正当な追加確認中 | なし |
| 精算可能 | 確認期間を終え、取消されず、出金申請へ予約されていない報酬 | ownerが申請可能 |
| 申請中 | 出金申請へ原子的に予約済みで、外部送金の確定前 | 同一申請を再作成しない |
| 送金済み | provider eventと台帳で送金完了を確定 | なし |
| 取消 | 確認中に返金・取消が確定し、取消entryを追記済み | なし |

通貨を跨いで合計しない。未確認、外部反映待ち、将来の見込み、推定手数料を精算可能額へ含めない。

## 4. 出金申請

- 主操作のラベルは、申請可能なら「出金を申請」、準備未完了なら「出金準備を始める」とし、同時に二つ表示しない。
- ownerの最近の通常再認証と現在permissionを確定時に再確認する。
- 申請額は精算可能額以下、正の最小通貨単位、許可通貨であることをserverで検証する。
- client mutation IDまたは申請IDにより再送を冪等にする。
- Stripe hosted onboardingから戻っただけで利用可能にせず、serverとWebhookが確定したcapabilityを再取得する。
- 外部結果が不明な場合は`pending_external`にし、新しい送金を自動作成しない。
- 同時申請は同じ台帳行を二重予約できない。競合した要求は最新残高を返して再確認させる。

## 5. 状態と受け入れ条件

- 0円、取得失敗、本人確認未完了、申請中、送金失敗を別表示にする。
- 金額は通貨と最小単位を常に表示し、負数・小数丸めを画面だけで補正しない。
- staff、owner、他Creator、permission失効、再認証期限切れ、同時申請、Webhook遅延をテストする。
- 申請後の再読込で、精算可能額と予約済み額の合計が申請前台帳と一致する。
- 取引明細からFanの連絡先、決済手段、カード、他Creatorの取引を取得できない。

精算ルールの正本は[クリエイター精算](../../operations/creator-settlement.md)とし、本書は画面表示と操作境界だけを所有する。
