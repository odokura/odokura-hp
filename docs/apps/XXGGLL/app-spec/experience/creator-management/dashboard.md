# Creator管理 概要画面

## 1. 画面契約

| 項目 | 仕様 |
| --- | --- |
| 画面ID | `SC-S02` |
| ルート | `/studio/[creatorId]` |
| read model | `RM-CreatorOverview` |
| 利用者 | 対象Creatorのowner、membershipが有効なstaff |
| 目的 | 次に確認する一件を選ぶ。全機能の縮小版を並べることではない |
| 主操作 | ownerの場合だけ「発行プログラムを作成」。staffへの作成permissionは未導入 |

## 2. 表示順

1. 共通対象バー。
2. `h1`「概要」と説明「要対応と、各業務の現在状態を確認できます。」
3. 要対応。優先度、期限、影響、移動先を持つ最大3件。
4. 現在状態。発行、保有関係、収益・精算の最大4指標。
5. 最近更新された発行プログラム。最大5件。
6. 各機能の状態行。利用可能、利用不可、取得失敗を区別する。

要対応が0件の場合は大きな成功カードを置かず、「現在、対応が必要な項目はありません」と一行で示す。4件以上ある場合は重要度、期限、更新時刻、IDの安定順で3件を表示し、「すべて見る」を該当業務画面へ置く。

## 3. 指標の定義

| 表示 | 定義 | 禁止 |
| --- | --- | --- |
| 公開中の発行 | `issuance_program.status = open`の件数 | 下書きや終了を合算しない |
| 現在保有されているXXGGLL | 現在保有者が存在し、回収・終了・archive済みでないXXGGLL件数 | 人数と呼ばない |
| 現在の保有者 | 対象CreatorのXXGGLLを現在一件以上保有する重複排除済みaccount数 | 複数保有を複数人と数えない |
| 精算可能額 | 台帳上で確認期間を終え、未予約・未精算で、現在申請できる通貨別金額 | 確認中や申請中を含めない。通貨を合算しない |

指標には`asOf`を一つ表示し、値ごとに異なる時点を混在させない。複数sourceの整合スナップショットを作れない場合は、sourceごとの時刻を表示して全体時刻を装わない。

## 4. 要対応の対象

要対応は、利用者がこの画面から実際に進められるものだけを返す。

| 種別 | 条件例 | 移動先 |
| --- | --- | --- |
| 発行設定 | 下書き、公開条件不足、審査差戻し、公開リンク失効 | 該当する発行プログラム詳細 |
| 精算 | 本人確認未完了、出金申請失敗、外部反映待ちの長期化 | 収益・精算 |
| 権限 | ownerにだけ必要な規約再同意、staff権限競合 | 設定・権限 |
| 提供物 | 法務確認差戻し、履行期限、公開停止 | 該当する別契約の提供物 |

staffに権限のない対応を見せない。対象の存在だけを示してownerへ依頼させる設計が必要な場合は、個人・金額・非公開理由を含めない専用の`owner_action_required`要約を別に定義する。

## 5. read model

`RM-CreatorOverview`は少なくとも次を返す。

| フィールド | 内容 |
| --- | --- |
| `creator` | `id`、表示名、公開状態 |
| `access` | `owner`または`staff`、列挙済みpermission、表示可能なナビ項目 |
| `asOf` | ISO 8601のサーバー基準時刻 |
| `attentionItems` | 最大3件の`type`、`severity`、期限、短い理由、許可済みroute |
| `metrics` | 定義ID、値、単位、source状態。取得できない値は`null` |
| `recentPrograms` | 最大5件のID、ランク、状態、発行数、現在保有数、更新時刻 |
| `sectionStatus` | 各業務の`available`、`not_available`、`failed` |

応答に個人保有者、プロフィール、支援表現、連絡先、決済手段、Stripe secretを含めない。`Cache-Control: private, no-store`を付ける。

## 6. 状態

| 状態 | 表示 |
| --- | --- |
| 読み込み中 | 対象バーと見出し位置を維持し、読込対象を一行で示す |
| 発行なし | ownerは作成操作、staffは「発行プログラムはありません」だけ |
| 要対応なし | 一行の正常状態。祝福演出や巨大な0を置かない |
| 一部取得失敗 | 取得済み区画は残し、失敗区画を「取得できませんでした」とする。0へ補完しない |
| 全体失敗 | 主データと操作を無効化し、同じ要求の再読込を一つだけ示す |
| 権限失効 | 対象を残さず共通`404`。別Creatorのcacheを表示しない |

## 7. 受け入れ条件

- 概要だけでAudienceの全グラフ、収益明細、提供物カード、staff編集フォームを展開しない。
- 「現在の保有者」と「現在保有されているXXGGLL」を同じ値・同じ単位にしない。
- 要対応のリンクは、利用者がアクセス可能な正規ルートだけを返す。
- 1件、複数保有する同一account、終了プログラムの現保有、回収済み、集計source失敗をfixtureで確認する。
- owner、permissionが一つのstaff、permissionなしstaff、失効membership、他CreatorをAPIと画面で確認する。
