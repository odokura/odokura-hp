# XXGGLL Publicフローページ仕様

## 1. 目的

Publicフローページ（`/flow`）は、XXGGLLを初めて見る人が、Creatorの発行からFanとCreatorへ
価値が戻るまでを一つの連続した体験として理解するためのページである。

機能一覧やデータ構造を説明するページにはしない。読み終えた人が、次の流れを自分の言葉で説明できることを
成功とする。

> CreatorがXXGGLLを発行し、Fanが個別リンクから購入する。取得時点の情報と、その後の支援や商品購入が
> Fan自身の記録へ積み上がる。Fanは活動記録で推し活の金額と来歴を振り返り、実績は利用区分の判定へ反映される。
> Creatorは同意された範囲の集計からファンを理解し、次の活動判断に生かす。

## 2. 画面契約

| 項目 | 契約 |
| --- | --- |
| ルート | `/flow` |
| シェル | Public |
| 利用者 | 未認証者、認証済みFan、発行を検討するCreator |
| 最重要の理解 | XXGGLLは購入時に完結せず、関係の記録、振り返り、集計、次のCreator判断まで循環する |
| 主要操作 | Creatorは`XXGGLLを発行する`、Fanは個別リンクから購入する方法を理解する、既存利用者はHomeへ戻る |
| データ境界 | 静的な表示例だけを使い、実在するFan、Creator、購入、支援、属性、集計を取得しない |
| 対象外 | Publicカタログ、検索、Creator一覧、実際の購入確定、個人ランキング |

## 3. Publicナビゲーション

すべてのPublicページのヘッダーは[画面台帳](./screen-catalog.md)のPublic共通ナビゲーションをそのまま使い、`XXGGLLの流れ`を1クリックで開けるようにする。

ブランド`XXGGLL`は`/`へ戻す。旧`XXGGLLとは`は`XXGGLLの流れ`へ統合し、Publicの主要な問い以外でナビ項目を増やさない。
デスクトップ、タブレット、モバイルのいずれでも、`XXGGLLの流れ`をメニュー内へ隠さず、表示中のリンクを
1クリックするだけで`/flow`へ遷移する。

## 4. ページ冒頭

冒頭はページ全体の答えを先に見せる。

- アイブロウ: `HOW XXGGLL WORKS`
- H1: `応援が記録になり、次の活動につながるまで。`
- リード: `XXGGLLは、Creatorが発行し、Fanが購入して終わるものではありません。応援の来歴をFanへ返し、同意された集計をCreatorの次の判断へつなぎます。`
- Creator操作: `XXGGLLを発行する`から`/start/creator`
- Fan案内: `購入は、Creatorから届く個別リンクから始まります。`

冒頭には全工程の小カード、統計値、架空の利用者、価格を並べない。一本の接続線と、後述する7段階の短いラベルだけで
ページ全体の進行を予告する。

## 5. 一つの連続したフロー

ページは次の7段階を、上から下へ一方向に表示する。デスクトップでは一本の進行線、モバイルでは番号で接続する。
各段階は、見出し一つ、説明二文以内、代表UI一つを上限とする。

### 01 Creatorが発行する

Creatorが、対象、XXGGLLランク、発行上限、価格条件を設定して一件の発行プログラムを公開する。
公開後、Creatorは推測困難な個別リンクを自分のSNS、商品同梱物等でFanへ案内する。

代表UIは一件の発行カードとし、Creator一覧や複数カードの比較を見せない。

### 02 Fanが個別リンクから購入する

Fanは案内された一件のリンクで、対象Creator、ランク、価格、期間、取得条件、役務が付かないことを確認し、
認証後も同じ対象へ戻って購入する。Publicトップやフローページから商品を検索・購入する導線は作らない。

B-01からB-04のいずれかが未解決の間は、表示例を`購入機能は現在準備中です。`の状態にし、購入確定CTA、価格、
手数料0円を表示しない。

### 03 取得時点がXXGGLLへ残る

購入が確定すると、FanのXXGGLLに発行No、取得日時、取得直前に正規連携元から確認したCreatorの
Xフォロワー数、XXGGLLランク、現在状態を記録する。X連携が失敗した場合は推定せず`未取得`とする。

ここで伝える結果は「その時から応援していたことを後で振り返れる」であり、番号やフォロワー数の列挙自体を
価値として扱わない。

### 04 過去の商品購入を登録する

Fanが正規販売元から受け取った未登録のXXGGLLコードを持っている場合、QRコードの読み取りまたはコード入力で、
過去の商品購入を自分のXXGGLLへ追加できる。商品名、正規販売元、購入確定日時、購入額、登録日時を来歴へ加える。

コードは購入確認済みの一回限りの値とし、QRコード内に氏名、住所、購入額その他の個人情報を直接埋め込まない。
手入力だけの購入、未確認のレシート、他人のコード、使用済みコードを登録させない。

物理XXGGLLカードに表示する現在状態確認用QRコードと、商品購入を登録する一回限りコードは目的を分け、
同じコードとして説明・実装しない。

### 05 Fanが自分の活動を振り返る

Fanの`/fan/activity`は、対象Creatorごとに、自分が応援へ支払った金額の推移と、取得、継続支援、追加支援、
登録済み商品購入を一つの来歴として表示する。

代表UIには次だけを表示する。

- 月別の支払額グラフ
- 累計支払額
- 一次支援、継続支援、追加支援、登録済み商品購入の内訳
- 取得時点から現在までの来歴
- 現在のユーザーランクと、次の判定に反映される実績区分

支払額とCreatorへの支援額を同じ数値にしない。税、手数料、二次流通の再発行価格、再発行クレジットは分け、
返金・取消しは元取引と対応させて集計する。正規販売元から購入額を確認できない商品は来歴には表示できるが、
金額グラフへ推定額を加えない。

### 06 実績が利用区分の判定へ反映される

一次支援、継続支援、追加支援、保有期間、確認済みの商品購入等は、ユーザーランクの判定材料として蓄積する。
画面は「何が反映されたか」と「現在の利用区分」を本人に示す。金額だけの進捗、到達保証、他者順位は表示しない。

`XXGGLLランク`、`ユーザーランク`、`クリエイターランク`を混同しない。購入したXXGGLLランクが支出額だけで
自動変化するように見せない。VIP・ExtraVIPのユーザーランクは、既存正本どおり運営の審査、招待、本人の承諾を
必要とし、自動昇格、金額だけの到達保証、公開順位を表示しない。

### 07 Creatorが集計を次の活動へ生かす

Creatorは、Fanが同意した範囲から作られた匿名集計で、地域分布、支援額帯、継続期間、XXGGLLランク分布、
登録された商品カテゴリの傾向を確認する。その結果を、活動地域、商品企画、発信内容、発行プログラムの設計等、
ファン全体のための次の判断に使える。

個人の住所、連絡先、決済情報、未同意属性、正確な個人支出額を標準表示しない。集計から個人を検索・選別・追跡し、
外部営業、差別的取扱い、購入承認へ使う機能は作らない。XXGGLLだけでCreatorに新しい制作、返信、発送等の
義務が発生するとも説明しない。

## 6. 情報の見せ方

- ページ全体を一つの循環として理解させるが、読み方向は上から下への一方向とする。
- 各段階の主語を`Creator`または`Fan`で始め、システムやデータベースを主語にしない。
- 各代表UIは実装予定の画面に似せたHTML/CSSの静的例とし、抽象図形だけで説明を終えない。
- 一つの代表Fanと一つの代表Creatorの関係を追うが、固有名、顔写真、実在値、架空の推薦コメントを使わない。
- 色は[デザイン仕様](./design.md)の共通tokenと`signal-stage`の許可範囲に従い、黄緑の進行線で段階を接続する。進行線は装飾であり、番号・主語・見出しの代替にしない。
- 1440pxでは説明と代表UIを左右交互に配置し、390px・320pxでは説明、代表UIの順に一列化する。
- モバイルで横向きの巨大フロー図を縮小表示しない。320pxで横スクロールを発生させない。

## 7. CTAと遷移

| 文言 | 配置 | 遷移先 |
| --- | --- | --- |
| `XXGGLLを発行する` | 冒頭、段階01、ページ終端 | `/start/creator` |
| `ファンに残るものを見る` | 段階05の後 | `/fans` |
| `クリエイターに分かることを見る` | 段階07の後 | `/creators` |
| `ログイン` | 未認証時ヘッダー | `/sign-in` |
| `ホームへ` | 認証済み時ヘッダー | `/home` |

Fan向けの汎用購入CTAは置かない。Creatorから受け取る個別リンクが購入入口であることを、冒頭と段階02で示す。

## 8. データ、プライバシー、セキュリティ

- `/flow`はPublicの商品、Fan、Creator、XXGGLL、取引、集計APIを呼ばない。
- 金額、グラフ、来歴、ランク、Creator集計は`表示例`と明記した静的プレースホルダーを使う。
- 商品購入額は正規販売元が購入確定とともに送った通貨・金額だけを記録し、Fan入力値や推定値を集計しない。
- QRコード等は推測困難な生コードだけを運び、サーバーはハッシュ照合する。生コードをDB、ログ、分析へ残さない。
- Creator向け表示は匿名集計を既定とし、少人数から個人を推測できる粒度を表示しない。
- 検索、公開カタログ、Creator一覧、人気、個人ランキング、他人の支出グラフを置かない。
- ページの説明自体をサイトマップへ含めてよいが、個別リンクは含めない。

## 9. アクセシビリティとモーション

- H1を一つとし、7段階をH2、段階内の補足をH3以下で表す。
- 進行線を読解の唯一の手掛かりにせず、番号、主語、見出しをテキストで表示する。
- グラフには同じ値の表またはテキスト要約を付け、色だけで内訳を区別しない。
- 全リンクをキーボードで操作でき、主要タップ領域を44px以上にする。
- `focus-visible`、`forced-colors`、200%拡大に対応する。
- `prefers-reduced-motion: reduce`では進行線、数値、グラフの自動アニメーションを停止する。

## 10. 受け入れ条件

| ID | 条件 | 検証 |
| --- | --- | --- |
| PF-01 | すべてのPublicヘッダーに`XXGGLLの流れ`があり、1クリックで`/flow`へ進む | DOM、リンク、ルート検査 |
| PF-02 | 冒頭だけで、発行、購入、記録、振り返り、Creatorの次の判断まで続く製品だと分かる | 1440px、390px、320pxの実画面 |
| PF-03 | 7段階が指定順で存在し、各段階に主語、行動、結果、代表UIがある | DOMと見出し順検査 |
| PF-04 | 取得時の発行No、取得日時、Xフォロワー数と、過去の商品購入コード登録が説明される | 文言検査 |
| PF-05 | Fan向けに月別支払額、累計、内訳、来歴、ランク判定への反映が表示例で示される | DOMと文言検査 |
| PF-06 | 商品購入額が未確認または不明な場合、推定して金額グラフへ加えないと読める | 文言と集計ロジック検査 |
| PF-07 | ランク3種を混同せず、VIP・ExtraVIPの自動昇格や金額だけの到達保証を示さない | 文言検査 |
| PF-08 | Creator向けに地域、支援額帯、継続期間、ランク分布、商品傾向と、その結果を活動判断へ使えることが示される | DOMと文言検査 |
| PF-09 | Creatorが個人を検索・追跡・外部営業できるように見せず、個別役務を約束しない | 文言と禁止要素検査 |
| PF-10 | Public API、実在データ、公開一覧、架空実績、個人ランキングへ依存しない | コード、通信、DOM検査 |
| PF-11 | B-01からB-04のいずれかが未解決中は購入確定CTA、価格、手数料0円、購入可能表示がない | 文言とリンク検査 |
| PF-12 | 1440px、390px、320pxで順序を保ち、重なり、文字切れ、横スクロールがない | 実画面と`scrollWidth` |
| PF-13 | キーボード、focus-visible、reduced motion、forced colors、グラフ代替情報を満たす | 操作と計算済みスタイル検査 |

## 11. 実装範囲と検証証拠

初回実装範囲は、`/flow`の静的なPublic説明ページ、Public共通ナビ、レスポンシブ、アクセシビリティ、
静的表示例とする。実際の決済、商品コード登録、支出集計、ランク判定、Creator集計の機能実装は別Issueとする。

実装時は次を残す。

- `/flow`と共通ナビの変更差分
- PF-01〜PF-13の自己判定
- ナビ、段階順、文言、リンク、禁止要素、API非依存のテスト出力
- 1440px、390px、320pxのページ冒頭、段階04〜07、終端のスクリーンショット
- キーボード、グラフ代替情報、focus-visible、reduced motion、forced colorsの確認結果
