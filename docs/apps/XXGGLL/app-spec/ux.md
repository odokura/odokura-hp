# XXGGLL UX

## シェルと閲覧境界

| シェル | 利用者 | 表示範囲 |
| --- | --- | --- |
| Public | 未認証者 | 製品世界と仕組みの説明、外部案内から開く対象限定の取得ページ、Creator開始、認証 |
| Home | 認証済み利用者 | 本人の保有XXGGLLカード、本人が管理する発行XXGGLLカード、要対応 |
| Studio | クリエイター・スタッフ | 発行XXGGLLの設定、匿名集計、収益、提供物 |
| Ops | admin | 審査、通報、返金、精算、監査 |

- Publicの主対象はサービス説明または一つの`public_entry_link`であり、公開一覧ではない。
- Homeの主対象は本人の`certificate`と、本人が管理権限を持つ`issuance_program`である。`creator_profile`自体を発行カードとして表示してはならない。
- Studioの主対象はセッションで認可された一つのクリエイターと、その配下の一つの発行プログラム、提供物、集計、収益またはスレッドである。
- Opsの主対象は一つの要対応ケースまたは監査対象である。全運用操作を一画面へ並べない。
- シェル、ナビゲーション、APIはサーバー側の閲覧コンテキストで同じ権限を適用する。
- 所有、所属、有効利用権を満たさない詳細・一覧・検索・通知はデータ本体を返さず、存在を示さない。
- メニュー非表示だけで権限を制御しない。
- デスクトップは左サイドバー、ページヘッダー、可変コンテンツ領域を使う。モバイルはシェル専用の下部ナビゲーションを最大4項目まで表示する。
- タップ領域は44px以上、キーボード操作、フォーカス、エラー要約、色以外の状態表示を必須とする。

## Public

```text
/                         サービス説明と外部案内方法
/flow                    XXGGLLの発行、購入、記録、振り返り、Creator活用を説明するPublicページ
/start/fan                ファン向け開始導線。ログイン・登録と外部案内リンクの利用方法
/start/creator            クリエイター向け開始導線。ログイン・登録と発行開始
/entry/[publicLinkId]     クリエイターが配布する推測困難な個別リンク。対象の有料XXGGLLの説明と取得開始
/entry/[publicLinkId]/confirm 認証済み利用者が同じ対象の条件・金額・期限を確認し、取得を確定する
/sign-in                  ログイン、登録、X OAuth、パスワード再設定
```

- トップページは、Fanの応援が消えずに振り返れることと、Creatorがファン全体の輪郭を次の活動判断に使えることを最初に示す。発行No、取得日時、取得時のXフォロワー数、グッズ購入は、その結果を裏づける一件のXXGGLLとして製品表示で示す。主ナビは`XXGGLLの流れ`、`ファンに残るもの`、`クリエイターに分かること`、`安全性`、`ログイン`または`ホームへ`とし、すべてのPublicページから`/flow`へ1クリックで進めるようにする。
- `/flow`は、Creatorの発行、Fanの個別リンク購入、取得時点の記録、商品コード登録、Fan本人の支払額グラフ・来歴、ユーザーランク判定への反映、Creatorの匿名集計と次の活動判断を一方向の流れで説明する。実在データやPublic APIを使わない。
- Fanは取得したいXXGGLLの個別リンクから直接始める。トップに汎用のFan開始操作を置かず、公開カタログ、検索、クリエイター一覧へは遷移させない。
- Creatorには、XXGGLLを発行して設定・統計を管理する公開入口を示す。登録・ログイン後は共通ホームの発行開始へ遷移する。
- Publicに検索、カテゴリ、クリエイター一覧、関連提供物、無料コンテンツ一覧を置かない。
- 個別リンクは内部検索・サイトマップの対象にせず、推測可能なIDを使わない。
- 個別リンクには対象、価格、残数、取得条件、証票取得が個別役務を発生させないことだけを表示する。
- `publicLinkId`は`public_entry_link`のランダムな生トークンであり、連番、プログラムID、クリエイターIDを使わない。サーバーはハッシュだけを保存し、生トークンをログへ出さない。
- 失効、取消、期限切れ、非公開プログラム、停止中クリエイターの個別リンクは、対象や理由を開示せず同じ`404`応答にする。
- 取得操作は`/sign-in`を経由しても、ログイン、登録、OAuth、メール確認の完了後に同じ`/entry/[publicLinkId]/confirm`へ戻す。継続先は同一Originの許可済みルートだけをサーバー側で受け付ける。
- 取得確認画面は、対象、ランク、価格、手数料、合計、通貨、残数、仮押さえ期限、支払済み期限、次回決済日、停止期限、取消・返金条件、証票取得だけでは個別役務が発生しないことを表示してから、一つの確定操作を受け付ける。

## 共通ホーム

```text
/home                     ファンとクリエイター共通のホームダッシュボード
/fan/supports             自分が所有した証票の一覧
/fan/supports/[id]        自分が保有または申込んだ一件の状態、来歴、更新、返還、再発行
/fan/catalog              有料XXGGLLを保有する本人の保有先に紐づく提供物
/fan/messages             自分に有効な利用権または担当ケースのスレッド
/fan/messages/[id]        自分に有効な利用権または担当ケースの会話
/fan/activity             自分の決済状態、領収、通知
/fan/profile              プロフィール項目と項目別開示設定
/fan/settings             認証方法、連絡先、セッション、支払方法
```

- 認証済みのすべての利用者は`/home`をホームとする。FanとCreatorでダッシュボードの基礎構造を分けない。両方の役割を持つ利用者には、保有カードと発行カードを同じ画面に表示する。
- ファンには、現在保有するXXGGLLをカード一覧で表示する。各カードはクリエイター、ランク、証票番号、状態、支払済み期限、次回操作を示し、本人の`/fan/supports/[id]`だけへ遷移する。
- クリエイターには、本人が管理権限を持つ`issuance_program`を一件一枚の発行XXGGLLカードとして表示する。`creator_profile`一件をカード化して複数プログラムの件数だけを要約してはならない。各カードはクリエイター、ランク、公開状態、発行数・上限、要対応、最新の匿名集計を示し、本人が認可された`/studio/[creatorId]/offers/[id]`だけへ遷移する。
- クリエイターには、発行カード一覧の先頭に「XXGGLLを発行」ボタンを表示する。`ランク選択 → 下書きの発行カード作成 → 設定 → 公開`の順で進める。下書きカードは作成直後から設定画面と統計画面の入口を持つが、公開前は外部案内リンク・購入・集計値を公開しない。
- 有料XXGGLLの初回取得は `外部案内の個別リンク → 内容確認 → 条件同意 → 決済/取得確認 → /home` とする。
- カタログは有料XXGGLLを保有する利用者だけに表示し、本人の保有先に紐づく提供物だけを返す。
- 証票一覧は現在・過去に分割しない。各証票を一つの連続記録として表示し、失効・譲渡・終了は時刻と状態を来歴に残す。
- プロフィールは独立した属性共有ページを作らない。各項目について、保有中の有料XXGGLLに紐づくクリエイターだけを開示先として選択・撤回できる。
- VIP DMの提供設定、他利用者、請求設定をFanに表示しない。

## Studio

```text
/studio                           所属クリエイターの選択、未完了オンボーディング
/studio/[creatorId]               所属先の要約、公開状態、要対応、匿名集計
/studio/[creatorId]/offers        所属先の提供物・プログラム
/studio/[creatorId]/offers/new    種類選択から始まる作成
/studio/[creatorId]/offers/[id]   下書き、公開、終了、条件編集
/studio/[creatorId]/audience      匿名集計と同意済み集計
/studio/[creatorId]/messages      所属先の提供物に紐づくDM・コンシェルジュ
/studio/[creatorId]/revenue       売上、保留、精算申請、送金状態
/studio/[creatorId]/settings      公開プロフィール、利用規約、チーム権限
```

- URLの`creatorId`ではなく、セッションの所属先だけを受け付ける。
- 発行カードの作成は`/home`から開始し、`ランク選択 → 下書き作成 → /studio/[creatorId]/offers/[id]`へ遷移する。設定完了後に公開審査または公開へ進む。
- クリエイターには個人の連絡先、決済情報、未同意のプロフィール項目を返さない。
- `/studio/[creatorId]`は所属先の要約と要対応への入口に限定する。発行条件の編集・終了は`/studio/[creatorId]/offers/[id]`、提供物は`offers`、属性は`audience`、メッセージは`messages`、精算は`revenue`へ分離する。
- `audience`は人数、ランク分布、期間推移、地域分布、支援額帯、継続期間、登録済みグッズの傾向、同意済み項目の匿名集計を表示する。支援者名、匿名識別子、XXGGLLの発行Noによる個人一覧・検索・選別を標準機能にしない。

## Ops

```text
/ops              要審査・要対応・障害の優先キュー
/ops/users        ユーザー検索と読み取り専用の画面確認
/ops/users/[id]   対象ユーザーのHome・保有XXGGLL・プロフィール・設定・Creator管理対象の確認
/ops/reviews      公開審査、通報、例外判断
/ops/payouts      精算、返金、送金
/ops/audit        監査ログの読み取り専用画面
```

- admin以外にはOpsの存在を示さない。
- 管理者は対象ユーザーを一人選び、そのユーザーに表示されるHome、保有XXGGLL、プロフィール、設定状態、Creator管理対象をOps内の読み取り専用ビューで確認できる。ユーザー本人のセッションへ切り替えず、ユーザー向けAPIへ管理者例外を追加しない。
- ユーザー検索一覧では識別に必要な最小情報だけを表示する。連絡先、プロフィール値、保有・支払の詳細は一件詳細を開いた後だけ表示し、誰がどのアカウントを閲覧したか監査記録を残す。
- ユーザービューから購入、返還、更新、同意変更、メッセージ送信、公開、精算その他のユーザー操作を実行できない。
- 返金、失効、終了、停止、送金は対象、理由、利用者・クリエイターへの影響、結果を確認して一度だけ実行する。
- 全操作を監査記録する。

## 状態と操作

| 状態 | 表示 | 許可する操作 |
| --- | --- | --- |
| 読み込み中 | 対象と待機中 | 戻る、中断 |
| 空 | データがない理由 | 次の一手を1つ |
| 処理中 | 対象、開始時刻、二重操作防止 | 待機、必要時の中断 |
| 反映待ち | 外部決済またはWebhook確認中 | 再課金しない再確認、問い合わせ |
| 成功 | 結果、記録、次の導線 | 証票、応援状況、管理画面へ移動 |
| 要対応 | 原因、影響、期限、復帰方法 | 再試行、設定変更、問い合わせ |
| 権限なし | 最小限の説明 | ログイン、戻る |

- 決済、証票支援、更新、返還、再発行、出金、返金は、対象・金額・期限・取消条件を確認してから確定する。
- Webhook反映待ちは完了と表示せず、再課金を防ぐ。
- 320px幅から横スクロールなしで主要操作を完結できるようにする。

## ルート移行と廃止

次の表は最終構造へ移行するための規範である。旧ルートの画面を残したまま主ナビから隠すだけでは完了としない。

| 現在または旧ルート | 判定 | 正規の移行先 | 完了条件 |
| --- | --- | --- | --- |
| `/creator` | MERGE | 未登録者は`/start/creator`からオンボーディング、登録済み利用者は`/home`または`/studio` | 発行フォーム・管理カードを置かず、全内部リンク移行後に旧画面を廃止する |
| `/studio` | REBUILD | `/studio` | 所属選択と未完了オンボーディングだけを表示し、ownerとstaffの権限差をサーバー応答と一致させる |
| `/supporter` | MERGE | `/fan/supports`と`/fan/supports/[id]` | 一覧と詳細を別read model・別画面に分離し、内部リンクと決済復帰先を移行する |
| `/services` | MERGE | `/fan/catalog` | 有効な有料証票に紐づく本人向け提供物だけを返す |
| `/vip-dm` | MERGE | `/fan/messages` | 利用権のある本人のスレッドだけを表示し、公開商品一覧を作らない |
| `/creator/vip-dm` | MERGE | `/studio/[creatorId]/messages` | 所属・`messages_manage`権限をサーバーで検証する |
| `/creator/vip-invites` | MERGE | `/studio/[creatorId]/messages` | 招待とコンシェルジュを対象スレッドの状態として統合する |
| `/creator/payouts` | MERGE | `/studio/[creatorId]/revenue` | 収益、保留、出金申請、送金状態を対象クリエイター内へ統合する |
| `/free-certificates` | DEPRECATE | なし | UI、API、主要リンクを削除し、恒久的に`404`とする |
| `/paid-certificates` | DEPRECATE | `/entry/[publicLinkId]` | 一覧へは転送せず`404`。個別リンク取得が完成するまで有料取得を機能ゲートで停止する |
| `/attribute-sharing` | DEPRECATE | `/fan/profile` | 属性値と項目別同意をプロフィールへ統合し、旧ルートは`404`とする |
| `/vip-concierge` | MERGE | `/fan/messages` | 本人の担当ケースだけを表示する |
| `/admin`、`/admin/concierge`、`/admin/fixed-content` | MERGE | `/ops`、`/ops/reviews`、`/ops/payouts`、`/ops/audit` | 優先キューと一件単位の操作へ分離し、admin以外に旧・新ルートの存在を示さない |
| `/home` | REBUILD | `/home` | `certificate`単位と`issuance_program`単位の本人データだけを表示し、役割選択・公開カタログを置かない |

## 中心導線

```text
Fan:
外部の個別リンクを開く
```
