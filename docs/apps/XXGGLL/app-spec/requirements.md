# XXGGLL 要件

機能要件、非機能要件、権限、受け入れ条件を定義する。詳細な業務ルールは表内リンク先を参照する。

### 現在の実装ブロッカー

| ID | 状態 | 不足している事実 | 解除条件 | ブロックする範囲 |
| --- | --- | --- | --- | --- |
| B-01 | BLOCKED | 一次発行の`primary_price`に加算する利用者負担の決済手数料について、算定式、端数処理、確定時点、保存先、返金時の扱いが未定義。現行の一次発行APIは`primary_price`だけをStripeへ渡しており、取得確認画面が必須表示する「価格・手数料・合計」を再現できない | プロダクト・法務・会計の合意を正本、DDL、決済quote read model、台帳記録、テストへ同時反映する | `/entry/[publicLinkId]/confirm`の課金確定操作と有料取得の公開。個別リンクの発行、対象限定read model、認証後の同一対象復帰は先行実装してよい |

`B-01`は手数料を0円と仮定して解除してはならない。現行挙動を正当化するために画面から手数料行を隠すことも不可とする。

## 非機能要件

| ID | 要件 | 優先度 |
| --- | --- | --- |
| NF-01 | 台帳・証票状態・同意はサーバー側を正本とし、クライアントの入力だけで確定させない | 高 |
| NF-02 | 在庫仮押さえと二次流通購入は、同一証票・同一枠への同時購入を1件だけ成立させる | 高 |
| NF-03 | 台帳への書き込みは冪等かつ二重記帳とし、同一決済の二重計上を起こさない | 高 |
| NF-04 | 同意・台帳・証票状態遷移・運営操作は追記専用の監査ログへ記録する（[セキュリティ](./security.md)） | 高 |
| NF-05 | 本人確認書類の原本・カード情報を自社インフラに保存しない | 高 |
| NF-06 | クリエイター向け画面・APIから、法的氏名・住所・本人確認書類・決済情報を一切取得できない | 高 |
| NF-07 | 運営の重大操作（強制失効・プログラム終了確定・返金）はadminロールに限定し、監査ログへ記録する | 高 |
| NF-08 | クリエイターによる個別プロフィール・支援額等の閲覧は監査ログに記録する | 中 |
| NF-09 | 待機需要の重複防止は、メールアドレス等の簡易な重複チェックに留める。個人を長期追跡する仕組みは持たない | 中 |
| NF-10 | 対応言語は日本語のみとする | 高 |
| NF-11 | 決済事業者・カード会社からの異議申立て、不正利用を示す合理的な資料又は公的機関からの要請がある取引だけを、最長180日まで精算保留できる。購入者の申告だけでは保留・返金確定をしない | 高 |
| NF-12 | カタログは有料XXGGLLを保有するアカウントだけに返し、対象は本人の保有先に紐づく提供物に限定する。未認証・未課金・無関係な対象への直接URL/APIは存在を示さない | 高 |
| NF-13 | Public、Home、Studio、Opsのルート、ナビゲーション、server read model、APIは同じシェル・所有・所属・permission境界を使う。旧ルートの表示非表示やクライアント側フィルタを認可に使わない | 高 |

承認ワークフローや役割別の専任コンソールは導入しない。

## 権限マトリクス

証票・台帳・属性データへのアクセスは役割ごとに最小化する。詳細な管理策は[セキュリティ](./security.md)の
「認証・認可」を正本とする。運営側は、想定運用規模に合わせて単一のadminロールに集約する。

| 役割 | 証票・台帳の参照 | 個別プロフィール・属性 | 台帳の書き込み | 運営操作 |
| --- | --- | --- | --- | --- |
| user（一般・VIP・ExtraVIP） | 自分の保有分のみ | 自分のプロフィール項目と開示設定のみ | 不可（購入操作経由のみ） | 不可 |
| creator | 自分宛ての集計・同意済み項目のみ | 同意済み項目のみ・個別閲覧は任意 | 不可 | 不可 |
| creator_staff | creatorが許可した範囲のみ | 同上（追加の最小権限） | 不可 | 不可 |
| admin | 全件 | 必要範囲・監査ログ付き | 可（訂正は取り消しエントリの追加のみ） | 可（監査ログに記録） |

adminは、台帳・返金の確認、通報対応、VIPコンシェルジュ対応、強制失効・プログラム終了の起票を行う。

## 機能実装の受け入れ条件

- 一般ユーザーが、外部案内の個別リンクから、アカウント作成後に本人確認・年齢確認なしで対象の有料XXGGLLを取得できる。公開カタログや検索を経由しない。
- 個別リンクから認証を開始した利用者は、ログイン、登録、OAuth、メール確認の完了後に同じ対象の取得確認へ戻る。外部URL、別対象、未許可ルートを継続先にできない。
- トップページでファンとクリエイターの開始導線が分かれ、認証後の共通ホームでは本人の保有カード・発行カード以外を返さない。保有カードは`certificate`一件、発行カードは管理可能な`issuance_program`一件に対応し、クリエイターは「XXGGLLを発行」から下書きカードを作成して同じ発行プログラムの設定・統計を表示できる。
- `/fan/supports`と`/fan/supports/[id]`は別画面・別read modelであり、一件詳細は現在状態と`certificate_event`の連続した来歴を返す。前保有者の個人情報は返さない。
- Studioのownerとstaffは同じmembership/permissionをナビゲーション、ルート、APIで使用する。audienceは匿名集計を既定とし、個人支援者一覧・匿名識別子検索を提供しない。
- Opsはadmin以外に存在を示さず、優先キューと一件単位の操作へ分離する。旧`/admin`の全操作フォームを一画面へ残さない。
- 廃止・統合対象の旧ルートは、主ナビ、主要リンク、決済復帰先、APIから到達不能であり、ファイルを残したまま非表示にするだけで完了としない。
- 一般ユーザーが、一次発行・二次流通いずれの経路でも有料証票をクリエイター承認なしに購入でき、
  在庫仮押さえ15分・自動解放が機能する。
- プロフィール内の項目別開示・撤回が、保有中の有料XXGGLLに紐づくクリエイター側の集計ダッシュボードへ正しく反映・削除される。独立した属性共有ページは表示しない。
- クリエイターが発行上限・価格モードを設定すると、ルールベースで実発行数・価格が算出され、クリエイター・
  運営が上書きできない。
- 証票の状態遷移（継続中→非継続→運営回収→新規発行枠、または→終了済み）が
  [取引ルール](../concept/general/transaction-general.md)の状態図どおりに動作する。
- 二次流通の再発行で、証票記録は引き継がれ、個人支援記録・属性・メッセージは引き継がれないことを
  API応答レベルで確認できる。
- 証票支援を行うと、支払った本人の個人支援記録と証票の累計額（`certificate.boost_total_amount`）の両方が
  更新される。二次流通の譲渡後、買い手には累計額だけが見え、誰がいつ支援したかの個別履歴は見えない。
- 追加商品・個別サービスの契約・決済・履行不能時の精算が、証票本体の状態と独立して処理される。
- 二次流通の成立時、前保有者へ現金送金をせず、再発行クレジットが正しく付与される。クレジットは他者移転・
  現金化・対象外役務への利用ができず、付与日から6か月で失効する。
- クリエイターは、購入のたびに個別対応することなく精算可能額を蓄積でき、任意のタイミングで出金を申請できる。
  申請額が未精算合計を超える場合、または既存の申請を含めて超える場合は拒否される。
- 出金申請前は運営のプラットフォーム残高に資金が留まり、クリエイター側の口座登録は出金申請時まで発生しない。
  精算先は、日本・JPYでrecipient capabilityが有効なConnected Accountだけに限定する。
- 管理画面のadminロールが、権限マトリクスどおりの範囲だけを参照・操作できる。
- 同意・台帳記帳・証票状態遷移・運営の重大操作が、すべて監査ログへ記録される。

## 機能ゲート

| 機能 | 有効化条件 |
| --- | --- |
| 有料証票・二次再発行・証票支援 | 推測困難な個別リンク、認証継続、Fanの取得確認、決済、反映待ち、返金、権限なしをE2Eで確認する |
| クリエイター収益・出金 | Studio/Opsの権限境界、Accounts v2 recipient capability、実送金、失敗復旧を確認する |
| 固定コンテンツ | 権利確認、保存、審査、停止、保有者への配信、譲渡後の表示範囲を確認する |
| 追加商品・VIP個別サービス | 証票と独立した条件、決済、履行、取消、返金、運用審査を確認する |
| VIP・ExtraVIPコンシェルジュ | 招待、匿名打診、同意、可視性制御、通報、停止をFan/Studio/Opsで確認する |
| VIP DM | 利用権、送信上限、安全導線、月次請求、返金、Webhookを確認する |
| 無料証票 | 提供しない |
