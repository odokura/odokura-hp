# XXGGLL コンセプト

> 応援を、公式な関係の記録として持つ。

## 定義

XXGGLLは、ファンとクリエイターの間に生まれた出来事を、一件の公式な関係記録として
取得・保有・表示できるデジタルプロダクトである。

一件のXXGGLLには、発行No、取得日時、取得時点のクリエイターのXフォロワー数を記録する。
正規販売元から購入確定を受けてXXGGLLが発行したグッズコードをファンが登録すると、
その購入も同じ関係の来歴へ加わる。
一次支援、継続支援その他のXXGGLL内の支援と合わせ、単発の決済では見えない関係の時間を残す。

「公式」とは、クリエイター本人または正規提供者が参加する運営管理下のプログラムであることを示す。
クリエイター本人が各保有者を個別に認知・推薦・保証していることは意味しない。

**XXGGLLの取得だけでは、クリエイターに個別の応答、制作、配信、物品提供、接客その他の役務は
発生しない。**

## 解決する課題

従来の投げ銭や購入は一度の決済履歴として終わりやすく、ユーザーの支援や関係が保有できる形で残らない。
一方、会員権や特典の販売は、クリエイターに継続投稿、個別返信、発送などの役務を発生させやすい。

XXGGLLは、役務の代わりに、運営が支援関係の記録、保有体験、属性共有を提供する。
これにより、ユーザーは応援を持ち続けられ、クリエイターは保有者数に比例する作業を負わずに
収益と支援者への理解を得られる。

## 中核原則

1. **特典ではなく関係を提供する**<br />
   全ランクの基礎価値は、XXGGLL、支援履歴、保有表示、同意した属性の共有に置く。

2. **XXGGLLは引き継ぎ、人は引き継がない**<br />
   XXGGLLの発行No・公開可能な来歴は譲渡できるが、前保有者の支援実績、グッズ購入履歴、属性、メッセージ、本人情報は譲渡しない。

3. **クリエイターの作業を保有者数に比例させない**<br />
   購入承認、個別返信、定期制作、発送、更新判断はXXGGLL本体に含めず、運営と自動化が処理する。

4. **属性開示を接触権にしない**<br />
   ユーザーは同意した属性と応援意思を届けられるが、閲覧、返信、面会は保証されない。
   法令上の本人確認が必要な対象コンテンツや役務は提供しない。

5. **証票取得と役務契約を分ける**<br />
   すべてのランクでXXGGLL取得だけでは役務を発生させない。VIP・ExtraVIPでは、双方の個別合意と
   別契約によって限定的な役務を追加できる。

6. **希少性は需要の結果とする**<br />
   供給を恣意的に絞って投機を煽らず、重複・不正を補正した需要とクリエイターの発行上限から
   ルールベースの計算式が発行数を決める。

## 提供価値

| 対象 | 提供価値 |
| --- | --- |
| ユーザー | 発行No、取得日時、取得時のXフォロワー数、グッズ購入を含む関係の記録、保有表示、自分の支援履歴、同意制の属性共有、公式な譲渡 |
| クリエイター | 個別役務を伴わない収益、地域分布・支援額帯・継続期間・グッズ購入傾向等の集計、同意済み属性の把握 |
| 運営 | 発行・保有・決済・譲渡・同意・必要時の法的確認・安全対応を一貫して管理する関係基盤 |

成功とは高額な転売を生むことではない。ユーザーが価値と境界を理解して安心して保有でき、
クリエイターが無理な作業を増やさずに関係と収益を継続できる状態を指す。

## 判断基準

- 法令、安全、権利保護を満たす。
- クリエイターの個別役務と判断回数を最小にする。
- 購入に本人確認を要求せず、アカウント作成から決済までの手続きを最小にする。
- クリエイター報酬の受領時だけ、Stripe Connectが求める確認をStripe上で行う。
- 個人的な認知、返信、面会を期待させる表現を使わない。
- 値上がり、買戻し、元本、流動性、収益を保証しない。
- 未決事項は、クリエイターの継続可能性とユーザーの理解しやすさを優先して決める。

## サービスの境界

- XXGGLLは通常のデータベースで管理し、NFT・暗号資産を使わない。
- 証票は物品、株式、配当商品、利回り商品ではない。
- すべてのランクで、継続投稿、個別返信、物品提供、無制限DM、常時応答をXXGGLL取得の対価に含めない。
- VIP・ExtraVIPの役務は、証票と分離した個別契約が成立した場合だけ提供する。
- 証票の譲渡は、著作権や前保有者の個人記録の譲渡を意味しない。
- VIP・ExtraVIP紹介は、面会・交際の仲介ではない。
- 性的サービス、出会いの仲介、違法なコンテンツを扱わない。

応援決済、二次流通、属性共有、プログラム終了、VIP・ExtraVIP役務の法的要件は、実装前に
専門家のレビューを行う。
