# 属性開示・条件付き本人確認

属性共有は自己申告情報を、ユーザーが選んだ相手・目的に限って共有する機能である。通常の登録、証票の取得・購入・保有・譲渡、属性共有にKYCは要求しない。

## 共有の原則

- ユーザーは共有先、項目、目的を選び、表示内容を確認して同意する。
- クリエイターには、同意された項目だけを表示する。
- 電話番号、住所、法的氏名、決済情報、本人確認書類、センシティブ属性は共有項目にしない。
- ユーザーは共有を撤回できる。譲渡時には前保有者の共有情報、メッセージ、確認マーク、支援履歴を引き継がない。

## 有償VIP DMの本人確認

KYCを使うのは、報酬額が0円より大きいVIP DMだけである。0円のVIP DMとそれ以外の機能には使わない。

1. ユーザーがProfileへ性別・生年月日・国籍を初回入力する。
2. Diditのホスト型フローで本人確認する。
3. サーバー処理中だけ、Diditの値とProfileの3項目を照合する。
4. 本人確認が成立し、3項目が全て一致した場合だけ確認マークを付ける。
5. SessionとKYC関連データを直ちに削除する。削除失敗時だけ再試行用のSession IDを短時間保持する。

不一致、中断、期限切れ、署名不正、重複Webhookでは確認マークを付けない。Profileの3項目は変更せず、確認マークを外す操作も作らない。

XXGGLLが保存するのは確認マークだけである。書類、法的氏名、Diditから返る属性、照合結果、Webhook本文、Session ID、KYC履歴は保存しない。確認マークは属性値を開示せず、クリエイターが書類や照合結果を見ることもない。

DiditのConsole設定は [Didit KYC設定](./didit-kyc) を参照する。
