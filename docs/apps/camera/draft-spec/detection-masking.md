# 検出とマスキング仕様

## 方針

- 検出は「補助」であり、最終判断と確認は常にユーザーが行う。仕様上も「完全自動で個人情報を消せる」
  とは謳わない。
- 既定はマスクあり（opt-out）。検出された領域は最初からマスクされた状態で提示し、見せたい部分だけ
  ユーザーが明示的に外す。
- 検出漏れは手動マスクで補う。自動検出は入り口であり、唯一の手段にしない。
- 書き出し時にマスクを画像へ焼き込み（flatten）、Exif やサムネイル画像としてマスク前の情報を
  残さない（→ [プライバシーとデータ取り扱い](./privacy-data.md)）。

## 検出対象（MVP）

| 対象 | 検出方式 | 既定動作 |
| --- | --- | --- |
| 顔 | オンデバイス顔検出（iOS: Vision Framework / Android: ML Kit Face Detection 相当） | 検出した顔をすべてマスク。タップで個別に解除可能 |
| （手動）任意領域 | ユーザー操作（矩形 / フリーハンド） | ユーザーが追加した領域のみマスク |

## 検出対象（Phase 2 以降・要技術検証）

| 対象 | 検出方式（想定） | 課題 |
| --- | --- | --- |
| 車のナンバープレート | 汎用物体検出モデル（自前学習または既存モデルの流用） | OS 標準 API がなく実現コストが高い。誤検出時の影響（ナンバー以外を隠す）も検討要 |
| 文字領域（住所・名前・電話番号等） | オンデバイス OCR + パターンマッチ | OCR で文字は拾えても「個人情報かどうか」の意味判定は困難。誤検知・見落としの両方が起きうる |
| QR / バーコード | オンデバイスのバーコード検出 | 直接個人情報を含むことは少なく優先度は低い |

Phase 2 で導入する場合も、検出結果はあくまで「候補」としてユーザーに提示し、確認を経てからマスクを
確定する。この扱いは MVP の顔検出と揃える。

## マスクスタイル

| スタイル | 説明 | 備考 |
| --- | --- | --- |
| ぼかし（ガウシアンブラー） | 強めのぼかしで判別不能にする | 既定 |
| モザイク | ブロック状のモザイク | 顔以外（文字・ナンバープレート等）にも有効 |
| 単色塗りつぶし | 黒などの単色矩形で覆う | 最も確実。デザイン上は目立つ |
| スタンプ | 動物の顔などのイラストで覆う | 子どもの写真向けの遊び要素。マスク領域より少し大きめに配置する |

マスクの強度（ぼかし半径・モザイクのブロックサイズ）は、書き出し後に元画像が復元困難な水準を
下限として固定する。ユーザーが下限より弱めることはできない（「隠したつもりで実は判別できる」を
防ぐため）。

## 編集操作

- 検出直後、検出した各顔にハンドル付きの枠を重ねて表示する。枠の見た目でマスク状態（オン / オフ）
  を示す。
- 枠をタップしてマスクのオン / オフを切り替える。
- 追加操作で手動マスク領域を追加する。矩形は 2 点ドラッグ、フリーハンドは指でなぞる。
- 追加した領域はドラッグで移動、ハンドルで拡大縮小、削除操作で削除できる。
- マスクスタイルは領域ごとに変更できる（全体一括変更のショートカットも用意する）。
- プレビューは常にマスク適用後の見た目を表示し、書き出し後の見え方と一致させる。

## 信頼度・限界の扱い

- 検出信頼度が低い場合（暗い、小さい、横顔など）、枠の見た目（破線など）で「見落としがあるかも
  しれない」ことを示す。
- 検出数が 0 件でも「検出なし」を静かに示すだけで、確認を強制するダイアログは出さない（過剰な
  警告で使い勝手を落とさない）。ただし手動マスクの入口は常に見える位置に置く。
