# 技術検証計画

実装着手前に確認する技術項目。プライバシー保護アプリとして、V-1〜V-3 が成立しない限り MVP 実装に
進まない。

## V-1: オンデバイス顔検出の精度・速度

- **確認**: 想定スタックから iOS Vision Framework / Android ML Kit Face Detection 相当の顔検出を
  呼び出せるか、フレーム処理の速度、集合写真（十数人）での検出率。
- **成功条件**: 一般的な行事写真で数秒以内に処理が終わり、実用的な検出率が得られること。
- **不成立時**: ネイティブモジュールの追加実装、または対応プラットフォーム構成の見直し。

## V-2: Exif 除去の実装方式

- **確認**: 使用予定の画像処理ライブラリで、位置情報などの Exif を確実に除去でき、書き出し後に
  情報が残らないことを検証する。
- **成功条件**: 書き出し後の画像を Exif ビューアで確認し、位置情報・端末情報が残っていないこと。

## V-3: マスクの焼き込み（flatten）と復元不可能性

- **確認**: 書き出し画像がマスク前の画素情報を含まない（レイヤーや、サムネイル・プレビュー画像に
  元画像が残らない）こと。特に HEIC / JPEG のサムネイル埋め込みに注意する。
- **成功条件**: 書き出しファイルから元の顔などを復元する手段がないこと。

## V-4: 車のナンバープレート検出の実現可否（Phase 2 判断材料）

- **確認**: 実用的な精度で動く学習済みモデルが、商用利用可能なライセンスで入手できるか、
  オンデバイスで実用的な速度が出るか。
- **成功条件**: 実用的な検出率とライセンス上の利用可否が確認できること。
- **不成立時**: Phase 2 から外し、手動マスクのみで対応する方針を維持する。

## V-5: OCR による文字検出と個人情報候補判定（Phase 2 判断材料）

- **確認**: オンデバイス OCR の認識精度、電話番号・郵便番号等のパターンマッチによる候補提示の有効性。
- **成功条件**: 候補提示が「見落とし防止のヒント」として実用的な精度で機能すること（過検知が
  多すぎて煩わしくならない）。

## 進め方

1. V-1（顔検出）を先行して確認する。MVP の根幹のため。
2. V-2・V-3（Exif 除去・焼き込み）を並行して確認する。プライバシー機能の根幹のため。
3. V-4・V-5 は Phase 2 着手前に確認する。

## MVP 着手ゲート

- V-1 が不成立なら MVP 実装に進まない。
- V-2・V-3 が不成立なら、外部ライブラリの選定をやり直す（プライバシー保護アプリの必須機能のため
  妥協しない）。
