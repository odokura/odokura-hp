# 設計判断と未決事項

確定した設計判断と、その理由を残す。仕様本体は各ページを正とし、ここは判断の要点をまとめる。

## 設計判断

| 判断 | 理由 |
| --- | --- |
| 既定はマスクあり（opt-out）。解除はユーザーの明示操作 | 検出漏れのほうが誤って過剰にマスクするより取り返しがつかない |
| MVP は顔検出 + 手動マスク + Exif 除去に絞り、ナンバープレート検出・OCR 自動検出は Phase 2 | OS 標準 API がなく実現コストが未確定なため、技術検証を経てから判断する |
| 動画のリアルタイムマスキングはスコープ外 | フレーム間追跡が必要で技術難度が高い |
| 顔認識による人物の同定・記憶は MVP で行わない | 生体情報の保存を伴い慎重な検討が必要なため |
| 元画像は書き出すまで写真ライブラリに保存せず、アプリ内保存も無期限にしない | マスクされないままの元画像が拡散するリスクを減らす |
| マスク強度は下限を固定し、ユーザーが下限より弱められないようにする | 「隠したつもりで実は判別できる」という事故を防ぐ |
| Exif の位置情報は既定オンから変更不可、撮影日時は既定で保持しトグルで除去可 | 位置情報は誤共有リスクが高く固定する。撮影日時は家族アルバム整理などの需要を考慮する |
| サーバーを使わず全処理を端末内で完結する | 他 ODOKURA アプリと同じく、プライバシーと運用コストの観点 |
| 安全機能（検出・マスク・Exif 除去）は無料、バッチ処理等の効率化機能を有料にする | 安全に直結する機能を課金対象にしない方針 |
| サブスクではなく買い切り中心の課金 | NeteClay と同様の方針 |

## 未決事項

| 論点 | 次に決めること |
| --- | --- |
| アプリの正式名称 | ブランディング検討時に決定する |
| 想定技術スタック（React Native / Expo か、iOS / Android ネイティブ別か） | [V-1](./tech-verification.md) の検証結果で判断する。NeteClay が Expo のため足並みを揃えるかも検討する |
| 元画像の自動削除期間の初期値 | 実利用フィードバックで調整する |
| ナンバープレート検出・OCR 自動検出の採否と Phase 2 投入順序 | [V-4・V-5](./tech-verification.md) の技術検証結果で判断する |
| スタンプ（マスク用イラスト）の絵柄バリエーション | デザイン検討時に決める |
| 複数言語対応の範囲 | 仮決定: 初版は日本語のみ |
